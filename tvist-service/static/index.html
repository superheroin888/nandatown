Why this exists

Five pain points a plain "send money" call can't solve

Everyone built agent-payment rails. Nobody built the dispute & escrow layer across them. Each card has a Prove it live button — it fires the real attack at the real API and shows the gate holding, in the console below.

Pain 1 · Irrevocability

Push payments don't come back

Pix, SEPA Instant, FedNow, UPI settle in seconds and are final. A wrong or fraudulent agent payment is gone — unless a lawful recall path existed before the money moved.

Pain 2 · Intent ambiguity

"Did the human actually authorise this?"

When agents transact, the dominant dispute becomes mandate scope. Without a consent vault, there's no proof of what the principal approved — and no basis to refuse or recall.

Pain 3 · Jurisdiction chaos

Every rail speaks a different dispute language

Pix MED 2.0 gives 11 days to recover; SEPA has SCT-Inst recall; FedNow has no federal recall standard. Reason codes don't translate. Agents need one canonical map.

Pain 4 · Blind prepayment

Paying before delivery, on a final rail

An agent that prepays on an irrevocable rail has zero leverage if the service never arrives. Escrow — hold until delivery is provable — is the natural construct. Nobody ships it rail-agnostically.

Pain 5 · Machine-to-machine trust

Agent swarms have no authority chain

Agents now delegate to sub-agents and trade with agents they've never met — with no enforcement that a sub-agent stays inside its delegator's authority, and no shared jurisdiction between two machines. One rogue sub-agent unwinds the whole chain of trust.

Layer 1

Region regimes

22 real instant/A2A rails, each encoded with irrevocability, recall window and dispute taxonomy. The Nash-bargaining recommender picks the jointly optimal jurisdiction.

Layer 2

Consent vault

The principal's explicit mandate — budget and merchant allowlist — stored before the agent moves a single credit, and enforced on every settle.

Layer 3

Value engine

Ledger + escrow + recall. Conservation-checked: balances plus holds are invariant across every pay / hold / release / recall sequence — watch total_funds in the live stats.

Key components

Five primitives, one API surface — every card runs live

Component

🗺️ Region recommender

POST /regions/recommend — reads each party's ranked list as ordinal utilities and returns the Nash bargaining solution: max uclient·uagent, tie-broken by maximin fairness. Client wants SEPA, agent wants UPI? It finds Pix — the fair middle. null = don't transact.

Component

🔏 Consent vault

POST /consent + enforcement inside /pay. A payment above the budget or off the allowlist is refused with 403 before funds move — the DigiDoot "explicit consent" model.

Component

🔒 Programmable escrow

POST /escrow → /deliver → /release. Funds leave the payer at open, reach the payee only when proof == condition_expected. Contest blocks release; refund makes the payer whole.

Component

↩️ Region-aware recall

POST /recall — reverses a settled payment only when the region permits recall and the payment provably breached the mandate. FedNow refuses; UPI/Pix honour a breach.

Component

⚖️ Dispute taxonomy

POST /dispute — accepts a case only if the reason code is valid in the agreed region. pix_med_return under UPI? Rejected. The canonical cross-rail translation table.

Component

🤖⇄🤖 Machine-to-machine trade

POST /m2m/delegate + POST /m2m/handshake — pure agent↔agent commerce on the same gates: attenuated delegation chains (a sub-agent's budget can never exceed its delegator's; traces to the root mandate) and a one-call pact — Nash region + mandate check + atomically funded escrow. No human in the loop; every refusal lands before funds move.

Component

⚡ x402 on-rail payments

GET /x402/resource/… — the HTTP-native agent rail: 402 Payment Required with structured requirements, retry with a signed X-PAYMENT header, receive the resource + an X-PAYMENT-RESPONSE receipt. Irrevocable regime; replays rejected; the principal's consent cap holds even on-chain.

Legal taxonomy · live from GET /taxonomy

Every dispute code is grounded in civil & commercial law

Tvist's reason codes aren't arbitrary strings — each maps to a substantive legal category with its civil-law and common-law doctrinal basis, and every one of the 22 jurisdictions carries its operative statutes, scheme rulebooks, and regulator with links to the official legal source. Agents cite the operative_basis when they file — an accepted /dispute returns the citation string inline; humans can verify every claim at the primary source.

⚠️ Disclaimer: technical demonstration only — a notional-credits sandbox, not a bank, payment institution, or law firm. Legal references cite real primary sources but are engineering-grade mappings, not legal advice; obtain qualified local counsel before relying on them in any jurisdiction. (GET /disclaimer)

Personas

Who calls Tvist — play each persona live

Persona

🛒 The shopping / booking agent

Job: spends its principal's money on flights, goods, subscriptions.
Without Tvist: prepays on final rails, overspends its mandate, no recourse.
With Tvist: escrows the fare, pays inside consent, disputes with valid codes.

Persona

🧑‍🦱 The principal (human)

Job: delegates — "book it, up to 500".
Without Tvist: discovers the 900-credit charge after settlement, on an irrevocable rail.
With Tvist: the 900 charge is a 403; a slipped-through breach is recalled.

Persona

🏪 The service-provider agent

Job: sells to agents it has never met.
Without Tvist: ships first and prays, or demands prepay and loses sales.
With Tvist: sees funds locked in escrow before shipping; paid the instant proof lands.

Persona

🏛️ The marketplace / platform

Job: hosts thousands of agent↔agent trades across borders.
Without Tvist: hand-rolls dispute rules per corridor, per rail, per regulator.
With Tvist: one call returns the jointly-optimal jurisdiction and its full regime.

API

Eighteen endpoints. Every snippet below is runnable.

# the fair jurisdiction for two parties who want different things  
curl -s -X POST $BASE/regions/recommend -H 'content-type: application/json' \
  -d '{"client_prefs":["eu_sepa","br_pix","in_upi"],"agent_prefs":["in_upi","br_pix","eu_sepa"]}'
→ {"agreed_region":"br_pix","method":"nash_bargaining","naive_client_first":"eu_sepa"}

# over-consent charge — refused before funds move  
curl -s -X POST $BASE/pay -d '{"ref":"p2","from_account":"alice","to_account":"shop",
  "amount":900,"region":"br_pix","consent_id":"c1"}'
→ 403 {"error":"payment 900 to shop exceeds consent c1"}

# escrow release before delivery — refused  
curl -s -X POST $BASE/escrow/e1/release
→ 403 {"error":"release condition not satisfied (not delivered)"}

# mandate-breach recall under UPI — honoured, citizen made whole  
curl -s -X POST $BASE/recall -d '{"ref":"u1","consent_id":"cb"}'
→ {"reversed":true,"reason":"mandate breach recalled"}
